# Go structure generator

[Project overview](../README.md) · [Viewer architecture](../docs/architecture.md) · [Development](../docs/development.md) · [OCTA format](../docs/octa-format.md)

`godocta/gen` is a standalone Go 1.22+ module with standard-library dependencies
only. It creates colored, ordered `.octa` structures for the Godot viewer. Godot
ignores this directory through `.gdignore`; Go is only needed to author or
regenerate builds.

## CLI

Run these commands from `gen/`:

```sh
go vet -composites=false ./...
go test ./...
go run ./cmd/octagen -list
go run ./cmd/octagen                      # All registered scenes into ../structures.
go run ./cmd/octagen castle arena         # Only named scenes.
go run ./cmd/octagen -out /tmp/octa-builds -density 8 castle
go test ./scenes -run TestScenesCompile/castle -v
```

| Argument | Default | Meaning |
| --- | --- | --- |
| `-list` | false | Print registered names/titles and exit without generating |
| `-out PATH` | `../structures` | Output directory, relative to the working directory |
| `-density NUMBER` | 2 | Cell-count multiplier relative to span 1 |
| Positional names | All scenes | Exact registered names, in requested order |

Put flags **before** scene names: Go's flag parser stops at the first positional
argument. All-scene generation is alphabetical. Unknown names exit with status 2;
build/write errors are reported per scene and cause status 1 after remaining scenes
are attempted. Successful lines report cell count, world bounds, and elapsed time.
Output directories are created as needed, and matching files are replaced.

Use a separate `-out` directory for density experiments. Checked-in builds use
`DefaultDensity` (2); regenerate them at that density after recipe changes.
`neighbors.octa` is a separate 15-cell fixture and is not generated by this CLI.

### Previews

`cmd/octapreview` renders `.octa` files to PNG on the CPU, with no window, GPU or
Godot, so it is the quick way to review a recipe after generating it:

```sh
go run ./cmd/octapreview castle                          # ../captures/preview/castle.png
go run ./cmd/octapreview -views hero -size 1800x1200 castle
go run ./cmd/octapreview -out /tmp/octa-previews ../structures/arena.octa
```

| Argument | Default | Meaning |
| --- | --- | --- |
| `-out PATH` | `../captures/preview` | Output directory; one `<name>.png` per input |
| `-views LIST` | `hero,side,front,top` | Studio camera views, laid out two per row |
| `-size WxH` | `1000x640` | Pixel size of each view |
| `-ss N` | 2 | Supersampling factor per axis |
| Positional args | required | Bare names resolve to `../structures/<name>.octa`; paths are read as given |

It draws exposed cell faces with flat shading and sun shadows over a neutral ground
and fits the camera to the whole build. World themes, X-ray and assembly need the
Godot capture tools described in [development](../docs/development.md).

### Density and units

Coordinates in recipes are world units with Y up; `Vec2.Y` means world Z in plan
view. `Cell` is an integer lattice coordinate, not a world-space point:

```text
span          = cbrt(1 / density)
world_center  = Cell.Center() * span = (X, Y, Z) * span / 2
cell_volume   = span^3 / 2
bulk cells per cubic world unit = 2 * density
```

| Density | Span | Linear resolution relative to span 1 |
| ---: | ---: | ---: |
| 1 | 1 | 1× |
| 2 (default) | ≈0.7937 | ≈1.260× |
| 8 | 0.5 | 2× |

Thus density 8 is approximately four times the cells of the default density 2,
not twice its linear resolution. Finite structures and boundary sampling change
exact counts. Authored dimensions remain fixed; their cell envelopes can shift
slightly as resolution changes. Use finite positive densities and stay below the
1,000,000-cell format cap. `Compile()` validates the resulting structure after
building; it does not enforce an allocation budget during rasterization.

## Packages and core types

The dependency direction is `cmd/octagen` → `scenes` → `kit` → `octa`; scenes may
also use `octa` primitives directly. `octa` has no dependency on Godot or scene code.

| Source | Types and responsibilities |
| --- | --- |
| [octa/geom.go](octa/geom.go) | `Vec3`, `Vec2`, `Box`; constructors `V`/`P`, plan/world conversion, vector and bounds operations, deterministic `Hash01` |
| [octa/lattice.go](octa/lattice.go) | `Cell`, `Neighbors`, `Nearest`, parity/range validation and volume samples |
| [octa/solid.go](octa/solid.go) | `Solid` interface, bounded predicates, primitives and constructive solid geometry |
| [octa/grid.go](octa/grid.go) | Mutable colored `Grid`, `Component`/`ComponentFunc`, `Order`, compilation into sorted data |
| [octa/palette.go](octa/palette.go) | Byte-sized `Color`, sRGB `RGB`, 16-color `Palette`, names and fallback colors |
| [octa/structure.go](octa/structure.go) | `Structure`, limits, validation, bounds, binary marshaling, file IO |
| [kit/medieval.go](kit/medieval.go), [kit/city.go](kit/city.go) | Plain-struct reusable components implementing `Build(*Grid)` |
| [scenes/scene.go](scenes/scene.go) | `Scene`, `Register`, `Get`, sorted `All`, `Compile`, `DefaultDensity` |
| [cmd/octagen/main.go](cmd/octagen/main.go) | CLI selection, generation, output paths, status reporting |

### Solids

`Solid` requires `Contains(Vec3) bool` and `Bounds() Box`. Bounds must enclose all
accepted points: grid iteration and CSG use them to skip work. Solids describe
continuous space; they do not themselves allocate lattice cells.

| Family | Available API |
| --- | --- |
| Rectangular | `Cuboid`, `Block(a, b)` (normalizes corners), `BlockAt(center, width, depth, y0, y1)` |
| Round | `Cylinder` (optional inner hole), `Frustum`, `Cone`, `Ellipsoid`, `Sphere`, `EllipticCylinder` |
| Architectural | `Prism` (plan polygon), `Gable`, `HipRoof`, `Arch` |
| Custom/linear | `Capsule` (thick segment), `Func{Box, F}` (bounded predicate) |
| Boolean | `Union`, `Subtract`, `Intersect`, backed by `UnionSolid`, `DifferenceSolid`, `IntersectionSolid` |
| Transform | `Translate`/`Translated`, `RotateY`/`Rotated`, `Sheared` |

Angles are radians. `AxisX` and `AxisZ` describe horizontal orientation; consult
each type's field comments for whether this is a ridge or opening direction.
CSG is evaluated at sample positions, not by clipping triangle meshes.

### Grid operations and color

`NewGrid()` has span 1. `NewGridWithSpan(span)` controls resolution, and `World(cell)`
applies that span; `Cell.Center()` alone does not. `Nearest(p)` also assumes span 1,
so use `AddAt()`/`HasAt()` for world points on a grid with another span.

| Operation | Effect |
| --- | --- |
| `Use(color)` / `Brush()` | Change/read the brush; default is `Stone` |
| `With(color, func())` | Temporarily change brush, restoring it after the callback |
| `Add(cell)` / `AddAt(point)` | Add a missing cell; `Add` validates coordinates and leaves existing color intact |
| `Fill(solids...)` | Occupy or repaint cells selected by each solid |
| `FillVolume(solids...)` | Occupy/repaint cells with more than half their sampled volume inside each solid |
| `Paint(color, solids...)` | Recolor occupied cells only; does not fill gaps |
| `Carve(solids...)` / `Keep(solid)` | Remove selected cells / remove everything outside a solid |
| `Build(components...)` | Apply components in order; later pieces may fill or carve earlier pieces |
| `Merge(other)` | Copy cells and colors, overwriting overlaps; use grids with the same span (no resampling) |
| `Cells()` / `ColorOf()` / `Has()` / `Remove()` / `Len()` | Inspect or edit occupancy; `Cells()` order is unspecified |
| `Bounds()` | Envelope of occupied centers, expanded by half a span |
| `Structure(title, order)` | Sort, attach palette/colors, and validate final data |

For span <1, `Fill`, `Paint`, `Carve`, and `Keep` accept a center if either its actual
position or its position rounded to the nearest half-unit is inside. Candidate
bounds are expanded by 0.25 where needed. This preserves seams between components
authored on half-unit steps and lets zero-thickness paint planes select a layer.
`FillVolume` instead tests volume samples at the actual cell scale; use it for
curved silhouettes such as the ship's hull or tower's mound.

The shared palette, in index order, is Stone, DarkStone, Sand, Brick, Terracotta,
Slate, Wood, Grass, Foliage, Water, White, Charcoal, Gold, Glass, Navy, Red. Files
embed their palette; viewers need no hard-coded Go color table. `Color.Or(fallback)`
treats zero (`Stone`) as unset. For component fields that use `Or`, requesting Stone
also selects the fallback; use a later `Paint` if necessary. `Building.Windows` and
`TwistTower.Windows` instead use zero to disable glazing.

### Ordering and storage

`Order` is `func(Vec3) float64`, evaluated on world centers. Lower keys arrive first
within each horizontal course. `Sweep(center, angle)` walks around a plan center,
`Along(direction)` follows a dot-product direction, and `Outward(center)` ranks by
radius. Final sorting is Y, order key, Z, X; a nil order uses Y/Z/X. A custom order
cannot override bottom-up Y ordering.

`Structure` holds `Title`, float32 `Span`, `[]Cell`, optional parallel `[]Color`,
and `[]RGB` palette. `Validate()` enforces the shared limits. `MarshalBinary()` and
`UnmarshalBinary()` implement v1/v2; `WriteFile()` writes a sibling `.tmp` then
renames it, and `ReadFile()` loads and validates. Uncolored data writes v1; nonempty
colored grids write v2. See the [format specification](../docs/octa-format.md).

## Reusable component catalog

Each component is a plain configuration struct implementing `Build(*octa.Grid)`.
Masonry generally uses the current brush, with scoped accent colors. Field comments
in the source give dimensions and defaults; component operations act on the shared
grid, so their order matters.

| Component | Purpose / key configuration |
| --- | --- |
| `Battlements` | Rectangular parapet; footprint, top, rim, period, merlon width |
| `RingBattlements` | Circular parapet; center, radius, top, rim, merlon count |
| `Wall` | Crenellated block with optional hollow gallery |
| `Tower` | Hollow round storeys, slits, corbelled parapet; `RoofBattlements` or `RoofCone` |
| `Turret` | Slender conical tower, optional cantilever corbel |
| `Keep` | Rectangular storeys, windows, door axis, battlements, optional corner turrets |
| `Hall` | Hollow gabled building; `Ridge` selects AxisX or AxisZ (zero value AxisX) |
| `Gatehouse` | Arched passage along Z with flanking round towers |
| `Moat` | Carves a square channel from existing ground, optional bridge and water paint |
| `Building` / `Plain()` | Setback `Tier`s with cumulative heights and insets relative to the original footprint; optional windows and `Crown` |
| `Crown` | `CrownFlat`, `CrownSpire`, `CrownMast`, `CrownPyramid` |
| `TwistTower` | Chamfered square tower, hollow floors, windows, optional spire |
| `Wedge` | Triangular/polygonal plan extruded into a building |
| `Tree` | Wood trunk and foliage ellipsoid |
| `SuspensionBridge` | Oriented deck, arched towers, sampled parabolic suspension cables |

`Castle`, `Arena`, and `CruiseShip` expose dimensions on their structs for Go callers;
the CLI registers their defaults and only exposes density. Recipes use `Hash01`
where variation must remain deterministic. `Register()` replaces an existing entry
with the same name, so new recipes should use distinct names.

## Add a scene

Create a file such as `gen/scenes/courtyard.go`:

```go
package scenes

import (
    "godocta/gen/kit"
    "godocta/gen/octa"
)

type Courtyard struct{}

func init() { Register(Courtyard{}) }
func (Courtyard) Name() string  { return "courtyard" }
func (Courtyard) Title() string { return "Courtyard" }
func (Courtyard) Build(g *octa.Grid) octa.Order {
    g.Use(octa.Grass).Fill(octa.Block(octa.V(-10, 0, -10), octa.V(10, 0.5, 10)))
    g.Use(octa.Stone).Build(kit.Tower{
        Center: octa.P(0, 0), Radius: 4, Base: 1, Top: 12,
        Roof: kit.RoofCone,
    })
    return octa.Sweep(octa.P(0, 0), 0)
}
```

Then, from `gen/`:

```sh
gofmt -w scenes/courtyard.go
go vet -composites=false ./...
go test ./...
go run ./cmd/octagen courtyard
```

`TestScenesCompile` automatically visits the registry: every scene must validate,
be nonempty, stay within the cap, assemble bottom-up, and use at least three colors.
The example gets grass, stone, slate roof, and gold finial from the component.
Add the name to `_test_generated_builds()` in `tests/test_core.gd`, run the Godot
checks from the repository root, and review it with `go run ./cmd/octapreview courtyard`. The gallery
discovers the file on startup or after a successful save/refresh.

A world theme is optional: add a `courtyard` entry to `WorldTheme.themes()` to match
the embedded title's snake case. Without it, the build uses studio lighting. Update
the catalog and overview when adding the generated asset.
